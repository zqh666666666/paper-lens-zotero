# 循文 · Paper Lens

为 Zotero PDF 阅读器开发的中文精读插件。在 PDF 中划选文字，右侧「当前选段」自动跟随。展开「段落缓存」可以找回之前的选段，再点击「翻译」「讲懂这段」或「结合全文」阅读和追问。模型请求使用你自己的 API Key。

## 安装与配置

面向 **macOS Zotero 10.0.x**。从 **0.4.2** 起，可以在侧栏右上角的 **设置 → 侧栏外观** 选择「跟随系统」（默认）、「浅色」或「深色」。选择会立即保存，对所有循文侧栏生效，不改变 PDF 页面的配色，也不需要配置 API Key。各版本的测试范围见 [验证记录](VALIDATION.md)。

1. 在 [GitHub Releases](https://github.com/zqh666666666/paper-lens-zotero/releases/latest) 下载 `.xpi` 安装包。打开 Zotero → 工具 → 插件 → 齿轮 → Install Plugin From File，选择下载的文件。
2. 打开 PDF，使用 **工具 → 循文 · API 设置**。安装前已经打开的阅读器可能需要重新打开，工具菜单始终可用。
3. 填写服务地址、模型 ID 和 API Key，点击「测试连接」，成功后「保存设置」。测试会调用模型一次，只发送测试消息，可能产生少量服务商费用。
4. 在左侧划选原文。划选完成时，本插件在本地更新右侧选段并缓存文字。点击精读操作时才向配置的模型发送请求。

### API 配置

| 设置 | 填写方式 |
|---|---|
| 服务地址 | DeepSeek 可填 `https://api.deepseek.com`；其他兼容服务按其文档填写，例如 `https://your-provider.example/v1` |
| 模型 ID | 按服务商控制台/API 文档填写准确的模型名称；不把可变模型名写死在插件内 |
| API Key | 自己在服务商创建的密钥，直接填入插件，不需要发给开发者或聊天助手 |
| 总输入字数 | 默认 36,000；合计提示词、选段、追问、暂存段落、检索片段和对话历史，具体计数见下文 |
| 最大输出 token | 默认 2,400；回答过长被截断时可调大 |

插件使用 **OpenAI 兼容 Chat Completions**，支持 `Authorization: Bearer`、`messages`、`stream`、`max_tokens`。支持 SSE 流式回复及返回普通 JSON 的兼容服务。原生 Anthropic/Gemini 专用协议不直接支持，需兼容网关。远程地址要求 HTTPS，本机 localhost 可用 HTTP。服务地址可填 Base URL 或完整 `/chat/completions` 地址。

不同地址的 Key 分开保存；切换地址不会自动把旧 Key 发给新服务。Key 保存在 Zotero 的 Mozilla Login Manager 中，不写入普通配置、会话、笔记或日志。它不是 macOS 钥匙串；本机配置文件的保护由 Zotero/Mozilla 提供。

## 精读功能

- **翻译**：默认只给完整、忠实的中文译文，保留术语；不因选择“简短回答”而删减译文。本轮只提供选段原文。
- **拆解长句**　在「阅读工具 → 更多精读功能」或译文下方发起，解释句子主干、修饰关系和难点。
- **讲懂这段**：默认先解释核心问题；需要更多推理或例子时，点击该条回答下的“深入展开”。
- **结合全文**：在整篇 PDF 的可提取文字中检索相关页段，解释论证作用。
- **术语与符号**：查找本文定义、使用方式，补充基础。
- **方法走一遍**：输入输出、分步演示、伪代码或维度；自拟数字标记为教学示例。
- **公式分层讲解**：直觉、符号、推导、作用；可在选段框手动纠正提取结果。
- **追查实验论据**：比较对象、变量、指标、消融、支持范围。
- **段落缓存**　展开「段落缓存（数量）」即可查看页码和原文预览。点击「恢复」将该段放回当前选段，点击「删除」移除这一条。删除当前段后会切到剩余缓存中最近的一条。每条新选段最多 20,000 字符，列表按最近使用顺序分页。开启本地保存后，重开论文可继续使用缓存。
- **跨段比较**　点击「设为比较段」，再划选或恢复另一段，在「阅读工具 → 更多精读功能」中选择「跨段比较」。
- **阅读路线**：依据当前资料推荐本文内的阅读顺序。
- **理解自测**：先出题，在追问框回答，继续得到反馈。
- **连续追问**：在总输入预算内带入最近最多 4 轮对话，优先保留较近回答的末尾和本轮原文。
- **阅读记录**　每篇论文单独保存段落缓存、比较段、最近 30 轮对话和理解标记。生成回答时可以继续划选，回答卡片保留发出请求时的选段与依据。
- **保存笔记**　在回答卡的「写入 Zotero…」中选择「保存笔记」。笔记包含选段、回答、模型、时间和原文链接，保存在论文父条目下。独立附件会生成独立笔记。
- **导出会话**　在底部「会话操作 → 导出会话」中选择 JSON 或 Markdown，再指定本机保存位置。导出包括选段、回答、原文依据和理解标记。

展开「阅读选项」可调整解释深度、回答长度和发送范围。解释深度支持「从基础讲」「专业基础」「深入原理」，回答长度支持「简短回答」「适中长度」「详细展开」。收起时仍能看到当前三项设置。

发送范围支持「只发选段」「当前页」「全文检索相关段落」；它决定本轮新增的论文资料，追问仍可能带入历史对话。本次实际发送的选段和检索片段，以及总输入字数、带入／省略的历史与片段数量，显示在「本次使用的原文」中。

拖动面板左边缘调整宽度，或聚焦该边缘后使用左右方向键；顶部 A−／A+ 调整回答字号，选段可折叠。宽度、字号、折叠状态、深度、长度和发送范围会在本机记住。回答结束后只更新变动的卡片，尽量保留正在阅读的位置和已展开的原文依据。

点击回答标题旁的页码、正文里的 `[P3-1]` 或「定位原文」会返回对应 PDF 页。能够唯一匹配的原文会短暂高亮。

## 阅读工具与写入 Zotero

在侧栏展开 **阅读工具**。新工具无需先划选正文，只有使用「当前选段」范围时才需要选段。

| 想做的事 | 操作 |
| --- | --- |
| 比较多篇论文 | 在「多篇论文问答」中从文库选择 2–6 篇 PDF 或加入已打开的 PDF，输入问题。循文在本机分别检索每篇原文；点击回答中的 `[D2-P3-1]` 可以打开第二篇论文的 PDF 第 3 页。 |
| 看懂图或表 | 打开对应页，展开「理解当前页图表」并点击「发送当前页图像并提问」。只发送这一页重新渲染的图像，不截取桌面、侧栏或已有标注。需要兼容图片输入的模型。如果日常模型只支持文本，可在「设置 → 读图服务」单独填写地址、模型和密钥。图像不会存入会话或导出文件。 |
| 自定义按钮 | 在「管理指令」中填写名称、提示词，选择当前选段、当前页、指定页段或全文。保存后就能点击按钮，也可随时编辑或删除。页段按 PDF 物理页序填写，如 `3–7`；如果所选原文超出预算，发送前会提示缩小范围。 |
| 改写已有笔记 | 在 Zotero 自带的笔记侧栏打开笔记，选中普通正文，再点循文「改写笔记选文」。审阅回答后，在回答卡的「写入 Zotero…」中替换原选文，或在笔记中设置光标后插入回答。修改可用 Zotero 自带的撤销操作恢复。笔记或原选区发生变化时不会覆盖旧位置。 |
| 保存 PDF 标注 | 在选段回答的「写入 Zotero…」中点击「将回答写入原选段标注」，原文会得到持久高亮，回答出现在标注评论里。读图回答可在原页创建便签。再次点击会定位到已创建的标注。跨论文回答没有唯一原选区，可保存为笔记。 |

新笔记、写入已有笔记的内容和 PDF 标注均遵循 Zotero 自身的文库权限和同步设置。切换论文或页码不自动启动模型。多篇问答按篇选取相关片段，不代表模型通读了整组论文。

## 数据与限制

- PDF 文本在本机提取。“当前页”只读取所选一页；随后做全文检索时复用已读页。当前进程最多缓存 5 篇，以文件大小和修改时间判断是否重读；不上传完整 PDF 文件。
- “结合全文”是**全文范围内检索相关片段**，不是每次把所有页送入模型。检索采用 BM25 词频/区分度排序、段落分块、选段上下文保留、任务线索、希腊字母归一化、部分中英文术语扩展及跨页去重。仍属于本地词项检索，不是语义向量检索，可能漏掉相关证据。
- 页码是从 1 开始的 **PDF 物理页码**，可能与印刷页码不同。引用链接仅表示该页段已提供给模型，不代表自动核实了论据是否支持结论。
- 当前版支持可提取的文字、公式文字和表格文字；支持通过视觉模型解读当前页图像，并可在用户选定的多篇本地 PDF 中检索；**不包含整本扫描件 OCR 或联网文献检索**。复杂公式与多栏 PDF 需要核对识别结果；无法读取时明确报错，可改用只发选段。
- 0.2.2 会比对原始文字层和排好阅读顺序的字符，按可识别字体恢复特定缺字，利用几何位置标注简单上下标。无法可靠定位的符号和检测到的二维布局会提示核对；请对照 PDF 在选段框改为清晰公式（可粘贴 LaTeX）再发送。手动修改优先。该功能不能自动把任意分式、矩阵或扫描件重建为 LaTeX。
- 总输入预算按消息的文字部分计算（单页 JPEG 单独限制尺寸，图像计费和 token 换算由服务商决定），包含系统提示、任务说明、资料 JSON 和其中的转义字符；不等于 token、字节数，也不包含完整 HTTP 请求封装。旧设置中的 `contextChars` 数值继续使用，但从 0.2.0 起约束上述总输入，不再只约束检索片段。
- 当前选段、追问、暂存段落和必要提示词不被静默截断；它们单独就超过预算时，会在发送前提示缩小输入或提高上限。其余空间统筹检索证据和最近对话，允许截取检索片段或较近回答的末尾，并在原文区显示取舍。
- 会话保存在 Zotero 数据目录的 `paper-lens/<libraryID>-<attachmentKey>.json`，默认不经本插件同步。最多保存最近 30 轮，追问带入最近最多 4 轮（每轮问题上限 2,000 字符、原选段上限 4,000 字符、答案保留末尾最多 6,000 字符；总预算不足时还会进一步减少）。当前选段最多 20,000 字符。
- 启用本地保存时，流式输出有新内容则约每 3 秒保存一次进行中的会话，结束时再保存最终状态。重开后，已落盘的生成中回答标记为“已恢复未完成回答”，可继续回答。强制退出或断电仍可能丢失尚未写入的最近内容；保存失败会提示。无法读取的旧会话文件不会被普通保存静默覆盖。
- 同一论文的多个窗口共享段落缓存、比较段、对话历史和理解标记，每个窗口有独立的当前选段。继续回答使用该条回答原有的选段、比较段、证据片段和正文末尾，仍受本轮总输入预算约束。
- 关闭本地保存不会删除已有文件；「清空会话」会清空当前论文的本地记录。保存为 Zotero 笔记后，笔记遵循你现有的 Zotero 同步设置。
- 不自动使用其他插件保存的 Key。卸载插件不会主动删除凭据或会话，若不再需要，请先在设置中删除 Key 并清空会话。
- 版本更新采用手动安装。在 GitHub Releases 下载新版 `.xpi` 后重复安装步骤即可升级。

## 开发与验证

运行时使用随包内置的 KaTeX，无需安装 npm 依赖或连接 CDN。开发需要 Node.js 18+、Python 3。

```sh
npm test
npm run check
npm run benchmark
npm run build
```

构建生成 `dist/paper-lens-<版本>.xpi`，包含 `manifest.json`、`bootstrap.js`、`LICENSE` 和 `src/`。安装包采用固定 ZIP 时间戳，便于复现。

代码组织：`src/core.js` 为提示词、总输入预算、配置校验、Markdown 解析和链接纯逻辑；`src/retrieval.js` 为本地检索；`src/pdf-text.js` 恢复文字层缺字并标注公式布局风险；`src/locations.js` 为原文与 PDF 字符矩形的匹配；`src/math.js` 为公式识别与排版入口；`src/plugin.js` 为 Zotero 适配、流式 API、凭据、侧栏和会话；`src/panel.css` 为阅读界面样式。

项目原创代码采用 [MIT 许可证](LICENSE)。内置 KaTeX 保留其[版权声明和许可证](src/vendor/KATEX-LICENSE.txt)，打包来源见 [PROVENANCE.md](src/vendor/PROVENANCE.md)。检索测试引用的论文片段由原权利人保留权利，出处与页码见[测试数据](tests/fixtures/retrieval-papers.json)。

检索评测使用 3 篇公开论文的 9 条短引文，来源和预期页码见 `tests/fixtures/retrieval-papers.json`。当前 10 个正例中命中 9 个（Recall@1／@3 均为 0.90），3 个负例均返回空结果。问题与标签由实现代理检查和编写，不是独立人工标注；其中保留了一个未命中的中文改写例。这只是短片段定位检查，**不能当作整篇论文检索召回率或通用准确率**。完整 PDF 不随项目分发。

测试与已完成/尚未完成的验证见 [VALIDATION.md](VALIDATION.md)。

## 0.2.2 术语与公式更新

- 根据本轮原文触发术语提示，区分“角域包络”“融入物理先验的目标函数”，以及衰减相对于上升的**不对称性**与作者明确定义的**比值**。不把另一篇论文的术语带入当前回答。
- 在本次论文中恢复了式 (24) 奖励项前的减号、`1.89 × 10⁻⁴`、`7.28 × 10⁻¹¹` 及负的置信区间下界。选区核验支持跨页和暂存段落；来源的提取警示随检索片段发送，保留旧会话中的证据快照。
- 真实复杂公式复测正确解释了“先平方再平均”、幅值占比、分母稳定项和负奖励的作用。仍应核对索引处的标量与整条向量的区别，以及范数比所需的非零条件。数学表达式能排版不代表解释已经过数学验证。

## 0.2.1 真实 API 复测与提示词修正

- 翻译明确只处理当前选段，直接开始译文，避免把“完整翻译”误解为整篇论文翻译并添加资料不足声明。
- 简短讲解以约 250–450 个中文字符、最多三个自然段为目标；增加分子／分母顺序与百分比／百分点核对要求。仍由模型遵循，不会硬截断回答。
- 使用 `deepseek-flash` 对同一摘要完成四次请求。修订后翻译直接从译文开始，讲解从 892 缩短至 588 个字符（含引用等，正文 438 个汉字），衰减／上升比的顺序正确。
- 仍有术语措辞生硬、引用偏密和无关提醒；部分 PDF 公式提取会丢失负号／上下标。完整对照和验证边界见 [VALIDATION.md](VALIDATION.md)。

## 0.2.0 阅读与恢复更新

- 回答长度与深度分开；翻译默认只输出译文，长句拆解和深入解释由用户按需点击，每次展开都会产生一次新的模型请求。
- 可调宽度、字号和选段折叠；对话按卡片更新，保留阅读位置。同篇多窗口独立选段、共享历史。
- 引用尝试定位并短暂高亮原文。匹配保留大小写、负号和上下标区别，支持常见连字和英文换行断词；有歧义时只跳页。检索区别公式、图、表和章节编号，并关联相邻定义／解释段落；参考文献降权在附录开始后结束。
- 当前页按需读取；总输入预算包含全部消息内容。继续回答复用旧回答的证据快照。
- 流式会话定期保存、重开恢复部分回答，支持 JSON／Markdown 导出；本地 Git 和升级前备份提供源码回退依据。

上述行为已通过本地自动化测试；本轮实际安装、原生界面检查与真实模型输出的验证状态，以验证记录中的 0.2.0 节为准。

## 0.1.1 阅读体验更新

- 回答支持标题、加粗、列表、引用、代码块和表格；所有内容以安全 DOM 生成，不执行模型返回的 HTML、不加载远程图片。0.1.3 起数学公式可排版显示，复制内容仍保留 LaTeX。
- 每条历史回答都能展开自己的原选段与依据，重开论文后仍可查看。
- 未完成回答可点击「继续回答」，自动使用该条回答对应的选段和历史尾部。每次继续是一次新的 API 请求，可能产生服务商费用。
- 追问携带原选段，避免切换选段后把旧回答错当作当前段落的解释。快捷追问先填入输入框，由用户发送；支持 Cmd/Ctrl+Enter 发送。
- DeepSeek 官方端点默认使用快速回答，可在设置切换深入思考或服务商默认。此参数不会发送给其他兼容服务。测试连接使用快速模式，减少思考耗尽测试输出额度的情况。
- 流式回答降低重绘频率；向上翻阅时不会在每个流式片段到达后强制滚回底部。

DeepSeek 思考模式参数依据：[官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 0.1.3 公式与检索更新

### 公式排版

支持 `\( ... \)`、`\[ ... \]`、`$ ... $`、`$$ ... $$`，包括分式、根号、上下标、积分/求和、矩阵和多行 aligned 环境。代码块/行内代码不会被误排版。

- 在本机将 LaTeX 转成原生 MathML，无需第二个 API Key，不加载外部字体或图片。
- 鼠标悬停查看公式源码；复制回答及保存笔记继续保留原始 LaTeX，方便后续编辑。
- 不完整或不支持的表达式显示原文；排版只改变显示，不能修正 PDF 识别错误或判断公式是否正确。
- 使用内置 KaTeX 0.16.21（MIT），来源与许可证位于 `src/vendor/`；禁用可信 HTML/外链扩展并限制公式长度、宏展开和尺寸。

### 本地检索

按段落与句子边界分块，BM25 排序考虑词频、文档内区分度与片段长度。中文“消融实验”等常用提问可扩展到英文术语，`λ` 与 `lambda` 等希腊字母表示会归一化。术语功能偏重定义线索，实验功能偏重结果与对照；明确的 Eq./Figure/Table/Section 编号增加关联权重。

优先保留识别到的选段所在段落，去除完全重复片段，并适度增加跨页覆盖；参考文献区降低权重。原文展开区显示匹配词、定义/实验线索和字数截取情况，便于核对为什么选中了该段。

这不是跨语言通用语义检索，也不保证命中所有相关段落。旧会话保留原来的来源片段；新检索使用新的分块，页码链接继续指向对应 PDF 物理页。

### 0.1.3 界面调整

蓝灰阅读侧栏、独立选段和回答卡片、常用操作层次、紧凑快捷追问及深色配色。小高度窗口自动减少辅助文案，保留回答空间。

## 0.1.4 稳定性修复

- 快速连续点击精读操作时，同一面板只会启动一个请求；等待凭据读取时也可以停止，关闭面板后不会再发送待启动的请求。
- 插件正常关闭或停用时，等待进行中的回答结束保存，减少部分回答丢失的风险。强制结束进程或断电仍可能丢失尚未写入的内容。
- 普通 JSON 响应与流式响应一致处理输出截断：保留已收到的正文，标记为未完成并允许续写。响应格式损坏或接口返回错误时不会误报完成。
- 修复请求初始化失败后未清理请求记录的问题；停止发生在发送前时，不再继续发送。
- 续写旧回答时尊重该条回答原有的暂存段落设置，避免混入后来暂存的其他文字。
- 等待回答期间编辑的新追问草稿会保留；正在保存上一条回答时也会阻止重复发起请求。

本轮使用模拟 API、Zotero 接口和文件写入验证，未调用真实 AI 服务，也未改动本机 Zotero 配置或阅读记录。
